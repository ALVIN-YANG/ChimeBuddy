## 未建立的保证

- 当前已有桌面聊天尚无事件证据。CLI 探针的成功不能证明桌面旧会话已加载新 Hooks；需要用户重开桌面应用后发送消息复测。
- 未找到公开的“前台选中会话”通知，因此实现手动固定选择。后台活动、最近更新时间和 loaded thread 都不等于前台选择。

- 多显示器、其他全屏应用和 GIF 的全部编码变体未逐一验证。

## 操作

运行 `bash scripts/build.sh`，打开 `.build/ChimeBuddy.app`。点气泡底部“设置”可导入 GIF、切换模式或手动点评。自动点评默认关闭；开启后会使用 Codex 用量。当前手动固定的会话名显示在底部下拉框。

## 2026-11-06：切换后显示未命名的修复

根因不是单纯标题刷新。Codex 的输入建议后台任务也触发 UserPromptSubmit，使用临时会话；真实捕获的 `00000000-0000-4000-8000-000000000004` 请求明确属于 composer suggestion。公开 thread/read 对其返回 thread not loaded，而本聊天可读取预期名称（真实标题已脱敏）。旧代码错误地把所有该类型事件都当成用户聊天。

修复：事件先保存，只有 thread/read 成功返回正式会话元数据才允许参与自动跟随。无法确认的临时会话不改变选中会话或点评上下文；新会话元数据暂不可读时最多短暂重试三次。不依赖消息正文、语言或提示词前缀识别内部请求。

验证：

- 修复前新增 composer suggestion 回归断言失败，修复后通过。
- 使用磁盘中真实用户 Hook、真实后台建议 Hook，加上实时 thread/read 回放，确认仍跟随本聊天且上下文不混入内部请求。
- 实际原生窗口显示本次测试反馈（原文已脱敏）和正确聊天标题。
- 仅有 Stop、重复事件、乱序启动恢复、后台回复隔离、首次身份延迟确认等回归通过。
- 没有代用户操作 Codex 主界面，因此未声称完成跨两个桌面聊天的 UI 切换实测。
