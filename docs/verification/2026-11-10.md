# 2026-11-10：流式声音、自定义动作与设置闭环

## 本地回归

- `bash scripts/test.sh`：14 组通过。覆盖原有会话隔离/上下文/缓存，以及动作增删改、GIF 复制与源文件删除、131 个动作无数量截断、请求适配、SSE 碎片、PCM 缓冲、设置表单保存和校验。设置测试使用隔离目录，不读取或修改用户密钥。
- `python3 scripts/test-voice-integration.py`：七种预设均经本地 HTTP/SSE/WebSocket 服务，到原生 AudioQueue 输出。固定 PCM 的输入与已消费字节相等；401、SSE 提前断开、WebSocket 未收到 task-finished、播放中取消后再次播放均通过。显式设备 UID 路径通过，默认仍为跟随系统。
- 大于 64 KiB 的缓冲压缩回归覆盖 240,000 字节，修复实测时 `Data.removeFirst` 保留非零索引引起的崩溃。
- `bash scripts/build.sh` 与 `codesign --verify --strict` 通过，功能构建为 0.2.0 / build 4；最终发布构建为 0.2.1 / build 5，编译目标显式指定为 `arm64-apple-macos14.0`。签名仍为 ad-hoc，不等于 Apple 公证。

## 真实模型、服务与人耳

- `bash scripts/probe-actions.sh`：真实 Codex 独立临时请求返回文字“这回总算问对了。”，结构字段 `action=得意`。生产动作解析器选中导入 GIF；切换测试会话后停止并恢复默认，原会话的文字和标签缓存可恢复。测试不写入用户的会话或记忆。
- ElevenLabs 真请求已使用原始 PCM16 LE / 24 kHz / 单声道。连续三段：第一段完成，第二段开始播放后主动停止，第三段完成。最终测试模型 `eleven_v4_turbo`，中文年轻女声音色（具体 Voice ID 不写入公开验证记录），服务商标签为 `zh / female / young / beijing mandarin`。
- 最终 v4 Turbo 两段完整播放分别接受并消费 268,800 / 241,920 字节；首音频到达为 1,967 / 732 ms，软件记录 underruns=0。首包时间不是端到端人耳延迟，也不是延迟保证。
- 用户最初反馈未听到；随后将同一段真实 ElevenLabs PCM 分别交给系统播放器和伙伴播放器，用户确认“两段都听到了”。当时输出为系统默认蓝牙耳机。该人耳确认验证播放器出声，不代表对后来切换的音色或模型做了独立音质评价。
- 最终配置仅写入本机声音偏好，密钥写入钥匙串。`ChimeBuddy --check-voice-config` 在最终构建中可读取并校验已保存配置。测试配置没有写成其他用户的固定模型或音色。
- [官方 API 价格页](https://elevenlabs.io/pricing/api) 本次公开列出 v4 Turbo 与 Flash/Turbo 均为 $0.04 / 1,000 字符。该价格说明本次测试选择，不替代账号实际账单。[模型说明](https://elevenlabs.io/docs/overview/models)。

## 界面与运行

- `--export-settings` 导出三页 × 浅深色共六张原生视图；检查布局、保存/试听控件及滚动区域。导出使用隔离配置，不访问钥匙串，也不包含真实设备名称。
- 设置保存通过真实 AppKit 控件操作：服务商切换保留草稿；模型与音色可编辑；有效配置保存到隔离目录，无效 HTTP 地址不覆盖旧配置。
- 用户选定的应用头像继续沿用，设置内使用单色 SF Symbols。默认人物和紧凑气泡继续使用现有素材与布局。
- 新构建已重新启动，进程写出 `ready` 回执。只在当前会话有新回复时运行声音和动作；切回气泡缓存不会重播。

## 发布兼容性检查

发布前检查 Mach-O 发现旧脚本默认沿用本机 SDK 的 macOS 26 目标，与 Info.plist 的 14+ 不一致。0.2.0 安装包已撤回公开发布，源代码标签保留。0.2.1 在脚本中固定 macOS 14 编译目标；`vtool -show-build` 验证 minos=14.0。当前机器验证运行，未在另一台 macOS 14 设备上进行人机验收。
