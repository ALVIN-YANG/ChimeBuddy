# 当前会话自动吐槽验证（2026-11-06）

## 验收目标

点击 Codex 会话时伙伴切换上下文；仅当前会话的用户输入、AI 最终回复完成触发吐槽；各会话缓存隔离。气泡只保留会话名称、吐槽正文和关闭按钮。

## 环境和现场证据

- macOS，本机 Codex bundle `com.openai.codex`，安装版本 `26.1029.61003`，内置 CLI `0.166.0-alpha.6`。
- 当前进程日志有 `ownerRoutePath=/local/<UUID>`、`windowId`；`thread_stream_view_activity_changed` 没有 `rendererWindowFocused` 等字段，因此没有套用要求这些字段的旧版示例。
- 只读探针通过页面路由选定会话，再经公开 `thread/read` 成功读到相同 ID、真实标题与本地记录路径。没有读写 Codex 数据库、修改安装包或注入 IPC。
- 本机记录的新用户边界是 `event_msg.item_completed` 的 `UserMessage`；最终回复边界是 `event_msg.task_complete.last_agent_message`。普通 `response_item` 中的宿主上下文和 `AgentMessage` commentary 被排除。
- `bash scripts/check-current.sh --roast` 对当时选中的真实会话最新用户输入调用了生产 `CodexReviewer`，成功生成一句中文吐槽并持久化。此项是显式重放测试，不当作新的真实用户输入自动触发证据。
- 新版启动后，诊断记录显示真实页面 A → B 切换，A 恢复缓存、B 无缓存。没有向 B 发送测试消息或手动选择伙伴会话。
- 随后 B 的真实最终回复触发 `roastQueued → roastStarted → roastCompleted(displayed:true)`。B 属于另一个本地项目，证明主消息来源不受原项目级 Hooks 范围限制。
- 通过伙伴自己的辅助功能树和窗口截图确认，自动生成结果已经显示：只有会话名、一句吐槽、隐藏按钮，没有原先的“要听我的看法吗”、点评按钮或设置按钮。没有缓存时窗口只有角色。
- 最终构建重启后，同一会话记录 `sessionSelected(cacheRestored:true)`；只读检查脚本返回相同缓存且 `modelInvoked:false`。没有因重启或补载历史重复生成。

## 自动回归

`bash scripts/test.sh` 包含：

- 页面选择拥有上下文；用户消息、后台完成、内部任务不能改变选择。
- 当前进程日志过滤、点击路由切换、首页清空、多个窗口不猜测、旧进程隔离。
- 跨日志按事件时间排序，旧文件不能覆盖新选择；分段写入、UTF-8 半帧、文件替换后恢复。
- 只提取真实 UserMessage 与 task_complete，排除工具、思考、中间回复与宿主上下文；同回合追加输入保持独立消息身份。
- 用户与完成事件都能请求吐槽；启动历史、背景消息、模拟和暂停不触发。
- 模型上下文只含所属会话；切换恢复缓存、迟到结果归属、旧结果不能覆盖新结果、重启读取与去重。
- 原有动画与缓存持久化回归。
